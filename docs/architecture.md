# REAL: Recursive Environment-Agent Loop
**自律エージェントにおける同期的推論と非同期的環境変化の調停アーキテクチャ**

## Abstract
大規模言語モデル（LLM）をエージェントシステムの中核に据える際、最大の問題となるのは「思考の連続性（Coherence）」と「環境の可変性（Mutability）」の整合性である。従来のReActなどの単層ループモデルは、エージェントが排他的に環境を操作することを暗黙の前提としており、人間による並行的な介入（ファイルの直接編集など）が行われると、コンテキストの矛盾（ハルシネーション）を引き起こす脆弱性があった。

本稿では、この課題を解決するために **"REAL" (Recursive Environment-Agent Loop)** アーキテクチャを提案する。REALは、エージェントシステムを**「認知層 (L1)」「制御層 (L2)」「状態層 (L3)」**の3層構造として再定義する。本モデルにおいて、システムの全状態遷移は、エージェントによる**関数的な更新**と、人間による**外乱的な更新**の再帰的な合成として記述される。これにより、自律的なタスク遂行と、人間による非同期な介入を数学的に矛盾なく統合するフレームワークを提供する。

---

## 1. Introduction
LLMは本質的にステートレスな関数 $f(x)=y$ であり、時間概念や副作用を持たない。これを「エージェント」として振る舞わせるためには、外部に状態（メモリ）を保持し、自身の出力を次の入力へとフィードバックするループ構造が必要となる。

しかし、IDE（統合開発環境）のような現実的なアプリケーションにおいて、環境の状態を変更するのはエージェントだけではない。ユーザーである人間もまた、エージェントの思考プロセスとは無関係なタイミングで環境を変更しうる。この「同期的なエージェントのターン」と「非同期な人間の操作」をいかにして単一のコンテキスト内で扱うかが、実用的なエージェント構築の鍵となる。

REALは、このループ構造を単なる手続きの繰り返しではなく、異なる抽象度と権限を持つ3つの階層の相互作用としてモデル化することでこの問題を解決する。

## 2. World State Definition ($\Omega$)
システムが保持すべき「現在の世界」$\Omega_t$ は、以下の2つの要素の対として定義される。

$$ \Omega_t = (\mathcal{E}_t, \mathcal{H}_t) $$

### 2.1 環境状態 ($\mathcal{E}$: Environment State)
エージェントが操作対象とする実環境の客観的なスナップショットである。
*   例：ファイルシステムの内容、データベースのレコード、ブラウザのDOMツリー。
*   $\mathcal{E}$ は可変（Mutable）であり、ツール実行や人間による直接操作によって書き換えられる。

### 2.2 認識履歴 ($\mathcal{H}$: Epistemic History)
エージェントおよびユーザーが観測した事象の時系列ログである。
*   内容：思考プロセス、対話、ツールの実行コマンド、実行結果（標準出力やエラーログ）、システムイベント。
*   $\mathcal{H}$ は追記型（Append-only）であり、エージェントの主観的な「記憶」を構成する。

## 3. The REAL Hierarchy & Formulation
REALシステムにおける時刻 $t$ から $t+1$ への状態遷移は、以下の包括的な合成関数によって表現される。

$$ \Omega_{t+1} = \mathcal{S}\Big( \mathcal{C}\big( \mathcal{A}(\Omega_t) \big), \ \epsilon_t \Big) $$

ここで、$\mathcal{A}$ は認知層、$\mathcal{C}$ は制御層、$\mathcal{S}$ は状態層のダイナミクスを表し、$\epsilon_t$ は人間による非同期介入を表す。

### Layer 1: The Cognitive Layer ($\mathcal{A}$)
**役割: 思考と意図の生成（副作用なし）**
最上位に位置し、LLMの知能を純粋な関数合成としてカプセル化した層である。ここでは時間は離散的（ターンベース）に進む。
この層には「実行（$E$）」は含まれず、あくまで「何をしたいか（Action Proposal）」と「どうしたいか（Signal）」を決定する。

$$ (a_t, \sigma_t) = \mathcal{A}(\Omega_t) \equiv I(G(P(\Omega_t))) $$

1.  **射影 ($P: \Omega \to \text{Context}$)**
    *   現在の巨大な世界状態 $\Omega$ を、LLMのコンテキストウィンドウに収まる形式へ変換・圧縮する関数。
    *   履歴の要約、重要度の低いファイルの除外、システムプロンプト（役割定義）の注入を行う。
2.  **生成 ($G: \text{Context} \to \text{RawText}$)**
    *   LLM本体による確率的なトークン生成プロセス。
    *   Chain-of-Thought（思考の連鎖）を含んだ自然言語テキストを出力する。
3.  **解釈 ($I: \text{RawText} \to (a, \sigma)$)**
    *   非構造的なテキストをパースし、実行可能な構造化データに変換する。
    *   **$a$ (Action)**: ツール名と引数のセット（例: `write("main.js", code)`）。
    *   **$\sigma$ (Signal)**: ループ制御シグナル（後述）。

### Layer 2: The Control Layer ($\mathcal{C}$)
**役割: フロー制御と同期的なオラクル管理**
L1が出力した意図に基づき、実際に適用すべき「同期的な更新操作 ($u$)」を決定するディスパッチャ（State Machine）である。
**「ツールとしての人間の役割（Oracle Human）」** はここで定義される。

$$ u_t = \mathcal{C}(a_t, \sigma_t) = 
\begin{cases} 
  \text{Execute}(a_t) & \text{if } \sigma_t = \text{CONTINUE} \\
  \text{Oracle}_{\text{Human}}(a_t) & \text{if } \sigma_t = \text{HALT} \\
  \text{Finalize} & \text{if } \sigma_t = \text{TERMINATE}
\end{cases} $$

*   **CONTINUE (自律モード)**:
    *   L1が提示した行動 $a_t$（ファイル作成、コマンド実行など）を承認し、実行関数を呼び出す。
*   **HALT (Human-in-the-loop)**:
    *   エージェントが情報を求めている（`<ask>`）、あるいは確信度が低い場合。
    *   システムは一時停止し、外部入力（Oracle）を待つ。ここで人間が回答することは、計算機における `input()` 関数やAPIコールと同じく、**L2ループ内での同期的なサブルーチン**として処理される。
*   **TERMINATE (完了)**:
    *   タスク完了処理を行い、ループを停止する。

### Layer 3: The State Layer ($\mathcal{S}$)
**役割: 実世界の更新と調停（Type B: Human as Supervisor）**
最下層であり、L2で決定された同期的な更新 $u_t$ に対し、L1/L2のロジックとは無関係な**非同期の外乱 $\epsilon_t$（Supervisor Intervention）**を合成し、最終的な次世代の状態 $\Omega_{t+1}$ を確定させる。

$$ \Omega_{t+1} = \mathcal{S}(u_t, \epsilon_t) = \text{Apply}(u_t, \Omega_t) \oplus \text{Inject}(\epsilon_t) $$

*   **$\text{Apply}(u_t, \Omega_t)$**: L2から渡された正規の更新。ファイル書き込みや履歴へのログ追加を行う。
*   **$\text{Inject}(\epsilon_t)$**: 人間がUI操作などで直接行った環境変更（ファイル削除、移動、強制停止など）。
*   **$\oplus$ (Consistency Merge)**: 両者の変更をマージする操作。物理的な衝突（Race Condition）が発生した場合、常に $\epsilon_t$（人間の操作）を「正」として扱い、履歴 $\mathcal{H}$ にその旨を記録する。

---

## 4. Consistency Mechanism: Event Injection
REALの数理モデルにおける核心は、L3 における演算子 $\oplus$ の挙動にある。
人間が管理者（Supervisor）として $\epsilon_t$ を発生させた場合、それは L1 の認識（文脈）には存在しない情報である。これを無視すれば、次のターンで $\mathcal{A}(\Omega_{t+1})$ は、ファイルが存在する前提で推論を行い、エラー（幻覚）を引き起こす。

REALは **Event Injection** によってこの項を処理する。すなわち、物理的な変更 $\epsilon_t$ を、論理的な履歴イベント $h_{\epsilon}$ に変換し、強制的に $\Omega$ の履歴部分に加算する。

$$ \mathcal{H}_{t+1} \leftarrow \mathcal{H}_t + \text{Log}(u_t) + \text{Log}(\epsilon_t) $$

### 3次元から1次元への射影
これは、**「3次元的な物理操作（UI上のドラッグ＆ドロップなど）」を、「1次元的な言語履歴（`<event>User moved file...</event>`）」へと射影変換するプロセス**である。
次回の L1 ループ開始時、射影関数 $P$ は更新された $\mathcal{H}$ を参照する。これにより、LLMは「自分が計算していない間に、神の手（ユーザー）によって世界が書き換えられた」という事実を、自身の記憶の一部として認知し、新たな状況に適応したプランを生成できる。

---

## 5. Conclusion
REALは、エージェントシステムを単一のループではなく、役割の異なる3つの階層構造として定義することで、人間とAIの複雑な関係性を整理した。

1.  **L2 (Control Layer) における人間**:
    *   システムに呼ばれて値を返す **「関数 (Oracle)」**。同期的に対話に参加する。
2.  **L3 (State Layer) における人間**:
    *   システムの状態方程式に外乱項を加える **「演算子 (Supervisor)」**。非同期に環境を操作する。

この定式化により、REALは「自律的な思考の連続性」と「予測不能な実世界の操作」を、単一の数理モデル上で破綻なく共存させることを可能にしている。これは、IDEのような人間とAIが密接にリソースを共有する環境において、AIエージェントを実装するための標準的な理論基盤を提供するものである。
